OmniClaim Health

Enterprise System Design, MongoDB Schema Specification & REST API Blueprints

1. Executive Summary & Architecture Overview

OmniClaim Health is an enterprise-grade healthcare claims adjudication engine engineered on an immutable event-sourcing foundation. The platform coordinates complex multi-care claims (Medical, Pharmacy, Prescription, and Behavioral Health) under a cohesive Case aggregate using Tasks and Workbaskets.

Stage 01
Policy & Eligibility
Verifies family policy active window, patient member status, remaining family deductibles, and category caps.
Stage 02
Claim Intake & Ingestion
Ingests CPT/Rx procedure lines and executes exact and composite duplicate detection engines.
Stage 03
Evidence & DCN Audit
Mints legal Document Control Numbers (DCN) for superbills and chart notes; enforces deficiency gating.
Stage 04
Clinical & Fraud Adjudication
Scores fraud risk; licensed physician reviewers evaluate medical necessity and reclassify procedure codes.
Stage 05
Settlement & Disbursement
Computes allowable fees, applies deductibles and coinsurance, adjusts preliminary reserves, and authorizes vouchers.
Stage 06
Closed & Archived
Seals case history, archives all DCN artifacts, and retains the complete immutable event replay stream.

2. Authentication, Session Management & Backend User Identification

OmniClaim Health implements an enterprise JWT (JSON Web Token) + RBAC (Role-Based Access Control) authentication engine. Every incoming request must present a signed Bearer token in the HTTP Authorization header. The backend authenticateJWT middleware cryptographically verifies the token and mounts the user's verified identity directly onto Express's req.user context. Audit events in case_events extract the actor identity strictly from req.user, preventing client-side spoofing.

Authentication & Cryptographic Identification Flow

1. POST /api/auth/login { username, password }
2. Backend queries 'users' collection -> validates bcrypt.compare(password, user.passwordHash)
3. Backend mints JWT: jwt.sign({ sub, userId, role, workbaskets, doctorProfileId }, JWT_SECRET, { expiresIn: '8h' })
4. Client sends: Authorization: Bearer <JWT> on all subsequent requests
5. Middleware authenticateJWT: jwt.verify(token) -> mounts req.user = decoded
6. Route Guards: requireRole('DOCTOR_APPROVER'), requireWorkbasket('CLINICAL_REVIEW')
7. Audit Attribution: 'case_events' records actor: { userId: req.user.userId, name: req.user.fullName, role: req.user.role }

5. Implementation Boundaries & Production Hand-off

This design strictly decouples domain logic through SOLID specifications. For the 2.5-day delivery sprint, the application includes an in-app reactive MongoDB BSON engine. For enterprise production hand-off, the generated Mongoose models can be plugged directly into any Node.js/Express service connecting to MongoDB Atlas with zero schema rewrites.
